# Algorithm Visualization Design

## Goal

在算法题详情页加入可交互的算法执行可视化，让用户能够通过逐步状态变化理解题解，而不是只阅读文字和代码。第一阶段从“盛最多水的容器”开始，同时建立可扩展到滑动窗口、链表、二叉树、矩阵和图算法的基础结构。

## Scope

### Included

- 通用算法步骤播放器：上一步、下一步、自动播放、暂停、重置和进度显示。
- 统一的 `AlgorithmStep` 步骤数据结构。
- 面向数组类算法的 `ArrayRenderer`。
- “盛最多水的容器”的步骤生成器和可视化接入。
- 算法详情页中的可视化面板，位于原创面试复盘之后、本地题解摘录之前。
- 黑绿主题下的语义色：薄荷绿表示当前有效状态，青色表示指针或辅助信息，琥珀色表示关键变量，橙色表示被淘汰或需要注意的状态。
- 桌面端和 390px 移动端布局适配，以及减少动效模式支持。

### Excluded

- 不修改算法题库内容、题解文字、统计数据和路由结构。
- 第一阶段不接入真实 Python 代码执行，不在浏览器运行用户代码。
- 第一阶段不实现链表、树、图和动态规划渲染器，只为这些类型保留扩展边界。
- 不引入第三方动画或图表依赖；使用 React、TypeScript 和 CSS 完成可视化。

## Architecture

### Component boundaries

`AlgorithmStepPlayer` 负责播放状态和控制操作，包括当前步骤索引、播放定时器、播放速度、键盘操作和进度。它不理解具体算法。

`AlgorithmVisualizer` 负责把通用步骤交给对应渲染器，并组合播放器、说明栏和变量面板。它根据 `visualizationType` 选择数组渲染器，后续可扩展为 `linked-list`、`tree`、`grid` 和 `graph`。

`ArrayRenderer` 只负责展示数组快照、索引、指针、区间、比较状态和已淘汰元素。渲染器通过步骤中的语义字段工作，不直接读取题库对象内部的题解文本。

算法步骤生成器独立于页面组件。每道支持可视化的题目提供一个纯函数，将固定输入转换为完整步骤序列，保证上一步和下一步可重复、可测试。

## Data Model

```ts
type AlgorithmStep = {
  title: string
  explanation: string
  variables: Record<string, string | number>
  visualizationType: 'array'
  snapshot: {
    values: number[]
    pointers?: Record<string, number>
    activeRange?: [number, number]
    compared?: number[]
    settled?: number[]
    result?: number
  }
}
```

题目可视化配置通过题目 slug 选择，不改变现有 `AlgorithmProblem` 类型的必填字段。没有可视化配置的题目继续显示现有详情页内容。

“盛最多水的容器”步骤生成器使用固定示例数组，按双指针算法生成每一次比较、面积计算、最大值更新和指针移动的状态。每一步都包含可读说明，因此播放器可以复用于其他数组题目。

## Interaction

- 点击“下一步”进入下一个算法状态。
- 点击“上一步”回到上一个状态。
- 点击播放后按固定间隔自动前进，再次点击暂停。
- 点击重置回到第一步。
- 进度条显示当前步骤在总步骤中的位置。
- 播放到最后一步后自动暂停，不循环播放。
- `Space` 控制播放/暂停，左右方向键切换步骤；控件获得焦点时不拦截输入框行为。
- 在移动端控制按钮保持可点击尺寸，数组横向区域允许局部滚动但不撑破页面。
- `prefers-reduced-motion: reduce` 下保留步骤切换和信息更新，关闭连续过渡动画。

## Visual Direction

可视化面板采用与现有算法详情页一致的深绿层叠面板。数组元素使用稳定的固定宽度和高度，避免步骤切换造成布局抖动。

- 普通柱体：深绿表面和低对比边框。
- `left` / `right` 指针：青色标签和细线。
- 当前比较区间：薄荷绿边框或底部标记。
- 当前最大面积：琥珀色数值强调。
- 被淘汰的较短一侧：低透明度橙色提示。
- 当前步骤说明和变量面板与代码区保持足够间距，不将文字叠在图形上。

## Data Flow

```text
problem slug
  -> visualization registry
  -> algorithm step generator
  -> AlgorithmVisualizer
  -> AlgorithmStepPlayer state
  -> ArrayRenderer + explanation/variables
```

步骤序列在详情页加载时生成一次。播放器只保存索引和播放状态，避免每一帧触发算法计算。自动播放只改变当前步骤索引，渲染器根据当前步骤重新绘制。

## Error Handling

- 未注册可视化的题目不显示空面板，继续使用现有详情页。
- 步骤序列为空时显示“暂无可视化步骤”，并隐藏播放按钮。
- 播放定时器在组件卸载、路由切换和暂停时清理。
- 指针或区间索引超出数组范围时，渲染器回退为普通数组展示，不阻断详情页。

## Verification

- `npm run build` 必须通过。
- 进入“盛最多水的容器”详情页，确认可视化面板和所有控制按钮可用。
- 验证上一步、下一步、播放、暂停、重置和键盘控制的边界行为。
- 在桌面端和 390px 移动端检查数组、变量、说明文字不重叠且不撑破布局。
- 检查浏览器控制台无新增错误。
- 访问没有可视化配置的算法题，确认现有详情页内容不受影响。

## Future Extensions

后续只新增步骤生成器或渲染器：

- 滑动窗口复用 `ArrayRenderer` 的活动区间能力。
- 链表增加节点和指针渲染器。
- 二叉树增加层级布局渲染器。
- 动态规划和矩阵增加网格渲染器。
- 图算法增加节点、边和访问状态渲染器。

播放器控制协议和步骤数据的核心字段保持稳定，避免每接入一种算法就修改详情页结构。
